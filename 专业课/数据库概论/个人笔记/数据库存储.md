## 物理介质

顺序访问可以提高查询效率。预读是一个利用顺序读写的机制。

## 廉价磁盘冗余阵列(RAID: Redundant Arrays of Inexpensive Disks)

- 一种利用大量廉价磁盘进行磁盘组织的技术
- 价格：大量廉价的磁盘比少量昂贵的大磁盘合算得多
- 性能：大量磁盘可以提高数据的并行存取
- 可靠性：冗余数据可以存放在多个磁盘上，单个磁盘的故障不会导致数据丢失

两种冗余的机制：

1. 镜像冗余：一个逻辑磁盘由两个物理磁盘组成，写操作在每个磁盘上执行，如果其中一个发生故障，数据可以从另一个磁盘读取
2. 校验码冗余：通过纠错码来恢复磁盘阵列中部分磁盘损坏的数据

拆分机制：将数据拆分到多个磁盘上以提高传输率

1. 比特级拆分（Bit-level striping）
- 将每个字节按比特分开，存储到多个磁盘上
- 对于由4个磁盘组成的阵列，将每个字节的第i个比特位和第i+4个比特位写到第i个磁盘上，其存取速度是单个磁盘的8倍

2. 块级拆分（Block-level striping）
- 对于由n个磁盘构成的阵列，文件的第i块 存放在第(i mod n) + 1个磁盘上
- 一般都采取块级拆分

## RAID级别

- 镜像提供高可靠性，拆分提供高数据传输率
- 通过利用与奇偶校验相结合的磁盘拆分想法，可以实现以较低成本提供冗余的方案
- 不同的RAID级别，具有不同的代价、性能和可靠性

1. RAID 0: 块级拆分且没有任何冗余的磁盘阵列，用于高性能访问且数据丢失不十分重要的应用场合  
2. RAID 1: 带块级拆分的磁盘镜像，提供最佳写性能，一般用于类似于数据库系统中日志文件存储的应用场合  
3. RAID 3: 位交叉奇偶验证  
4. RAID 4: 块级拆分，在一个独立的磁盘上为其他N个磁盘上对应的块保留一个奇偶校验块  
   - 读取一个块只访问一个磁盘，每个存取操作的传输率低，但可以并行地执行多个读操作，从而产生较高的总I/O率  
5. RAID 5: 块交叉的奇偶校验。将数据和奇偶校验位分布到所有的N个磁盘上，即一个磁盘上包含其他磁盘的奇偶校验码  
   - 奇偶校验块不能和这个块对应的数据存储在同一个磁盘上  
   - RAID 5所有磁盘都参与对读请求的服务，而RAID 4中奇偶校验磁盘不参与读操作  
   - RAID 5包容RAID 4，在相同成本下提供更好的读写性能  

### 选择合适的RAID级别  

RAID 1 or RAID 5?  
   - 依赖于读/写的比率  
   - 为写1块数据，RAID 5需要2块读和2块写  
    如果应用需要每秒r次读，w次写  
   - RAID 1要求每秒r + 2w次I/O操作  
   - RAID 5要求每秒r + 4w次I/O操作  
   - RAID 5比RAID 1使用较少的磁盘可能是幻觉  
    当写操作较少且数据非常大时，RAID 5较优，否则RAID 1更佳

## 存储结构  

数据库物理上被分为文件组和操作系统文件，逻辑上被分为区间和页面  

数据文件被划分为8K的页面，每8个连续页面组成一个区间


Q: 如何为对象划分空间？
A: 两种方式：
1. GAM（全局分配位图）是一个页面，共8k字节，64k位，每一位对应一个区间，记录文件中每个区间是否被分配，一共可以表达4GB(64kx64k)数据空间。
2. PFS（空闲页空间）记录文件中每个页面是否已经被分配以及有多少空闲空间。每一个页面在PFS中有一个字节对应表达该页面的充满度，每个PFS覆盖8088个连续页面。

Q: 如何发现一个特定对象的区间或者页面？
A: IAM（索引分配位图）是一个页面，每一位代表一个区间，覆盖范围与GAM相同，位为1表示该区间被分配给该对象。一个对象每占据文件的4G空间，就需要一个IAM页面，对象的所有IAM页面构成一个双向列表。

# 索引

1. B+树
    B+树接而胖，二叉树高而瘦，B+树减少了磁盘访问次数，提高了查询效率。
    B+树与B树的不同之处在于：
    - B+树的非叶子节点只存储索引，不存储数据，因此可以大大减少数据占用的磁盘空间

2. Hash索引
3. 位图索引
    - 适用于列中取值只有几个的情况，列中的每一个值对应向量中的一位

4. 多维索引：
    - k-d树
    - 四叉树
    - R树（高维B树，二维形式下每个节点对应一个矩形区域）

5. LSM树（Log-Structured Merge-Tree）
基本思想：
    - 采用追加数据而不是原位更新，减少随机写
    - 将N个数据划分成多个小的有序结构，每m个数据在内存里排序一次，这样就获得N/m个有序结构；查询时从最新的一个有序结构里做二分查找，如果没找到就继续查找下一个有序结构；读取的时间复杂度是\( \text{N/m} * \log N \)。随着小树越来越大，内存中的小树会flush到磁盘中，磁盘中的树定期做merge操作，合并成一棵大树，以优化读性能

优点：
- 将随机写转化为批量的顺序写
- 将对数据的修改增量保持在内存中，达到指定的大小限制后再批量写入磁盘，所以写入性能大大提升
- 读取时需要先看是否命中内存，否则需要访问较多的磁盘文件

写入流程

- 来了一个 put (k, v) 操作，首先追加到WAL日志中，接下来加到C0层
- 当C0层的数据达到一定大小，就把 C0层和C1层合并
- 合并出来的新的new-C1会顺序写磁盘，替换掉原来的old-C1
- 合并之后所有旧文件都可以删除

查询操作

- 读操作需要依次读取 memtable、immutable memtable、SSTable0、SSTable1...直到找到数据或到达磁盘尾部。因为采用追加数据，这种查询方式能保证找到最新的数据
- 对于不存在的数据，则会白白遍历所有集合：引入布隆过滤器（多个哈希）来加速读操作，当它显示相应的SSTable中没有要读取的数据时，就跳过该SSTable

删除操作

- 当有删除操作时，并不需要像B树一样，在磁盘中找到相应的数据后再删除，只需要在memtable（内存）中插入一条数据当作标志，如delKey:1933
- 当读操作读到memtable中的这个标志时，就会知道这个key已被删除
- 在随后的日志合并中，这条被删除的数据会在合并过程中一起被删除

更新操作

- 和删除操作类似，都是只操作memtable，写入一个标志，随后真正的更新操作被延迟在合并时一并完成

缺点：

读写放大是 LSM-tree 的主要问题（read and write amplification）。读写放大 = 磁盘实际读写的数据量 / 用户访问的数据量

写放大：

- 以 Level Style Compaction机制为例，它每次拿上一层的所有文件和下一层合并，下一层大小是上一层的 r 倍。单次合并的写放大就是 r 倍
- 假如现在有三层，文件大小分别是：9，90，900，r=10。又写了个1，这时就会不断合并，1+9=10，10+90=100，100+900=1000，总共写了 10+100+1000

读放大：

- 为了查询一个 1KB 的数据，最坏需要读 L0 层的 8 个文件，再读 L1 到 L6 的每一个文件，一共 14 个文件
- 而每个文件内部需要读16KB的索引，4KB的布隆过滤器，4KB的数据块，一共 24*14/1=336倍
- key-value 越小读放大越大

## 查询处理

### 算子实现

1. 连接运算

- 嵌套循环连接（两层 for 循环逐行匹配）
  - 小表放在外面
  - 如果内存有限，尽量把内存给小表用
  - 如果有表建立了索引，把这个表放在里面

- 归并连接
  i. 在当前R和S块的前端查找连接属性的最小值
  ii. 如果这个值在另一个关系的前部没有出现，那么就删除具有这个值的元组
  iii. 否则，找出两个关系中的这个值的所有的元组，如果需要，从排序的R或者S中读取块，直到不再有其他的元组
  iv. 进行连接，输出和这个值相关的所有得到的结果元组
  v. 如果一个关系在内存中已经没有要考虑的元组了，那么就重新装载为这个关系而设定的缓冲区
  vi. 和归并排序的想法相同

- 散列连接
  - 适用于自然连接和等值连接
  - 基本思想：一个表作为生成输入，将所有键值hash到不同的桶中，另一个表作为探测输入，每一个键值hash后与对应桶中的键值比较，找到匹配的键值对
  - 一般小表作为生成输入，大表作为探测输入，避免大表全部加载到内存中

- 各种连接策略比较
  - 合并连接和哈希连接只能用于等值连接，对于非等值连接，只能用嵌套循环连接
  - 如果一个连接输入很小（比如不到10行），而另一个连接输入很大而且已在其连接列上创建索引，则索引嵌套循环是最快的连接操作
  - 如果两个连接输入很大，并且在二者连接列上排序（连接列上有索引），则合并连接是最快的连接操作
  - 哈希连接可以处理很大的、未排序的非索引输入
  - 如果两个连接输入都很大，而且这两个输入的大小差不多，则预先排序的合并连接提供的性能与哈希连接相似。然而，如果两个输入的大小相差很大，则哈希连接操作通常快得多

### 算子执行方式

1. 物化执行(Materialization)：中间结构存储到磁盘

- 生成输入为关系或已计算结果的表达式的结果，在磁盘上物化(存储)
- 从最底层开始每次计算一个运算，将中间结果物化成临时关系，再进行下一层运算
- 物化执行总是可用的
- 将结果写到磁盘并读回来可能代价很高

2. 流水线化(Pipelining)

- 当一个操作正在执行中，就将部分输出元组送到父运算
- 流水线执行：同时计算多个运算，将一个运算的结果传到下一个运算
- 比物化执行代价要低，不需要将临时关系存储到磁盘
- 有时流水线不可用 - 如排序和散列连接
- 为了使流水线有效，使用能在接受输入元组的同时生成输出元组的执行算法（无阻塞算子）
